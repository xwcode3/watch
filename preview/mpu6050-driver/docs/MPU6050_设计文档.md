### 2.2 与 AHT21 驱动的一致性对照

| 维度 | AHT21（现有） | MPU6050（本驱动） | 一致性 |
|---|---|---|---|
| 驱动实例类型 | `bsp_aht21_driver_t` | `bsp_mpu6050_driver_t` | 同构：ops 表 + 依赖注入 + 状态 |
| 实例化函数 | `aht21_instantiate()` | `mpu6050_instantiate()` | 挂 ops 表 + 走 init |
| ops 槽位命名 | `pf_init/pf_deinit/pf_read_id/pf_read_data/pf_sleep/pf_wakeup` | 同名 + 新增 `pf_read_raw/pf_reset` | 超集，风格一致 |
| 总线契约 | `iic_driver_interface_t`（`iic_bus_t*` 第一参数） | 同一契约头 `iic_interface.h` | **同一套** |
| 总线描述 | `{SCL,SDA}` 软件位带 | 扩展 `{i2c_periph, clk_speed, hw_enabled}` | 向后兼容 |
| Handler 线程 | `temp_humi_handler_thread` | `imu_handler_thread` | 同构（队列+lifetime+回调） |
| 错误码 | `aht21_status_t`（OK/ERROR/PARAM/NOT_INIT/ERRORTIMEOUT…） | `mpu6050_status_t`（同名风格 + ERRORBUS/BAD_ID） | 风格一致 |
| 全局访问点 | `gp_temp_humi_instance` | `gp_imu_instance` | 同构 |
| 有意差异 | Handler 直接持有具体驱动类型（剖析 §6.5 已列为债务） | Handler 持有 `imu_ops_t` + `void* dev` | **修复债务**：换芯不改 Handler |

> 有意差异说明：AHT21 剖析文档 §6.5 指出“Handler 直接耦合具体驱动类型”是下一步最有价值的重构。MPU6050 作为新增驱动直接采用目标形态（设备无关 ops 表 + 具名适配函数），既保持桥接手法一致，又不引入新的同类债务。

## 3. 桥接接口定义

### 3.1 总线契约 `iic_driver_interface_t`（与 AHT21 完全同构）

| 槽位 | 签名 | 语义 | 返回约定 |
|---|---|---|---|
| `pf_iic_init` | `int32_t (iic_bus_t*)` | 初始化引擎与引脚 | 1 成功 / 0 失败 |
| `pf_iic_deinit` | 同上 | 释放引擎 | 同上 |
| `pf_iic_start` | 同上 | 产生 START（等待 SB） | 同上 |
| `pf_iic_stop` | 同上 | 产生 STOP（等 BUSY 清） | 同上 |
| `pf_iic_send_byte` | `int32_t (iic_bus_t*, uint8_t)` | 发送 1 字节（等 TXE） | 同上 |
| `pf_iic_receive_byte` | `int32_t (iic_bus_t*, uint8_t* out)` | 接收 1 字节（等 RXNE） | 同上 |
| `pf_iic_wait_ack` | `int32_t (iic_bus_t*)` | **1=ACK，0=NACK/超时**（对齐 `IICWaitAck`） | 同上 |
| `pf_iic_send_ack` | 同上 | 主机回 ACK | 同上 |
| `pf_iic_send_not_ack` | 同上 | 主机回 NACK | 同上 |
| `pf_iic_bus_reset` | 同上 | 总线卡死恢复（硬件引擎提供） | 同上 |
| `iic_bus` | `iic_bus_t*` | 当前总线 | — |

> **为什么细粒度原语在硬件外设上仍成立**：硬件 I2C 的地址字节 ACK（ADDR 标志）与数据字节 ACK（TXE/BTF）在 `hw_iic_wait_ack` 内统一归一化为“ACK/NACK”语义；ADDR 的清除（读 SR1+SR2）在 wait_ack 内部完成，对驱动层透明。序列 `receive(N-1) → send_not_ack → receive(N) → stop` 在 400kHz（22.5µs/字节）下两次调用间隔远小于 1 字节时间，NACK 时序安全。

### 3.2 设备 ops 表 `imu_ops_t`（Handler 侧，设备无关）

| 槽位 | 签名（dev 为不透明上下文） |
|---|---|
| `pf_init` | `mpu6050_status_t (void *dev, const mpu6050_config_t *cfg)` |
| `pf_deinit` | `mpu6050_status_t (void *dev)` |
| `pf_read_data` | `mpu6050_status_t (void *dev, mpu6050_data_t *out)` |
| `pf_sleep` / `pf_wakeup` / `pf_reset` | `mpu6050_status_t (void *dev)` |

适配方式：`bsp_mpu6050_handler.c` 内 6 个具名静态适配函数（`ops_*_adapter`）把 typed self 转成 `void*`，**不使用函数指针强转**，规避 `-Wcast-function-type` 告警与未定义行为。

## 4. 硬件 I2C 配置说明

### 4.1 默认方案：I2C1 @ PB6/PB7，400kHz

| 项 | 配置 |
|---|---|
| 外设 | `I2C1`（APB1，默认 42MHz PCLK1） |
| SCL | **PB6**（AF4，开漏 + 上拉，High Speed） |
| SDA | **PB7**（AF4，开漏 + 上拉，High Speed） |
| 速率 | `I2C_ClockSpeed = 400000`（快速模式，`DutyCycle = 2`） |
| 地址模式 | 7-bit；自身地址 0x00（纯主机） |
| ACK | 使能（`I2C_AcknowledgeConfig(ENABLE)`） |
| GY-521 接线 | VCC→3V3，GND→GND，SCL→PB6，SDA→PB7，**AD0→GND**（地址 0x68），INT 悬空 |

与现有 AHT21（软件 I2C，PB13/PB14 位带）**互不冲突**：硬件 I2C1 使用 PB6/PB7 独立总线。两器件同地址空间也不冲突（0x38 vs 0x68）。

### 4.2 SPL 初始化代码（引擎内已实现，此处为逻辑说明）

`hw_iic_init()` 实际执行序列：

```c
/* 1. 时钟 */
RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOB, ENABLE);   /* 引脚端口 */
RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C1, ENABLE);    /* 外设 */
/* 2. 引脚 AF4 + 开漏 + 上拉 */
g.GPIO_Pin = GPIO_Pin_6 | GPIO_Pin_7;  g.GPIO_Mode = GPIO_Mode_AF;
g.GPIO_OType = GPIO_OType_OD;  g.GPIO_PuPd = GPIO_PuPd_UP;
g.GPIO_Speed = GPIO_High_Speed;
GPIO_Init(GPIOB, &g);
GPIO_PinAFConfig(GPIOB, GPIO_PinSource6, GPIO_AF_I2C1);
GPIO_PinAFConfig(GPIOB, GPIO_PinSource7, GPIO_AF_I2C1);
/* 3. 外设软复位（干净起点） */
RCC_APB1PeriphResetCmd(RCC_APB1Periph_I2C1, ENABLE);
RCC_APB1PeriphResetCmd(RCC_APB1Periph_I2C1, DISABLE);
/* 4. 外设参数 */
i.I2C_ClockSpeed = 400000;  i.I2C_Mode = I2C_Mode_I2C;
i.I2C_DutyCycle  = I2C_DutyCycle_2;
i.I2C_OwnAddress1 = 0x00;   i.I2C_Ack = I2C_Ack_Enable;
i.I2C_AcknowledgedAddress = I2C_AcknowledgedAddress_7bit;
I2C_Init(I2C1, &i);  I2C_Cmd(I2C1, ENABLE);
I2C_AcknowledgeConfig(I2C1, ENABLE);
```

> 若 SPL 版本较老无 `GPIO_High_Speed` 宏，等价替换 `GPIO_Speed_100MHz`（stm32f4xx_gpio.h 中两者同值 0x03）。

### 4.3 备选外设方案（引脚冲突时）

| 方案 | 外设 | SCL | SDA | 代码改动点（仅集成层 `iic_bus_mpu6050` 一个结构体） |
|---|---|---|---|---|
| B | `I2C2`（APB1） | PB10 | PB11 | `.scl_port=GPIOB, .scl_pin=GPIO_Pin_10, .sda_pin=GPIO_Pin_11, .i2c_periph=I2C2` |
| C | `I2C3`（APB1） | PA8 | PC9 | `.scl_port=GPIOA, .scl_pin=GPIO_Pin_8, .sda_port=GPIOC, .sda_pin=GPIO_Pin_9, .i2c_periph=I2C3` |

引擎的时钟/复用映射函数 `hw_iic_rcc_on()` / `hw_iic_gpio_config()` 已按外设与端口自动分支，**换总线只改数据结构，不改任何代码逻辑**——这正是桥接模式“实现维度可替换”的收益。

### 4.4 CubeMX 引脚核对步骤（仅规划用途，不生成 HAL 代码）

1. 新建/打开工程 → MCU 选 STM32F411CEU6；
2. Pinout 视图 → 点击 PB6 → 选 `I2C1_SCL`；PB7 → `I2C1_SD A`（自动成对出现）；
3. Connectivity → I2C1 → Mode: **I2C**；Parameter: Speed = 400000（Fast Mode）；勾选确认无绿色冲突标记；
4. 对照本表核对：无其他外设占用 PB6/PB7；SYS 引脚、AHT21 的 PB13/PB14 不受影响；
5. **不要**在 CubeMX 中生成 HAL 代码到现有 SPL 工程——本步骤仅用于人工核对引脚冲突。若使用备选方案 B/C，在 Pinout 中同样只做核对。

## 5. 初始化序列（逐条寄存器说明）

实现位于 `mpu6050_init_impl()`。默认配置：±2g / ±250°/s / DLPF 44Hz / 采样率 100Hz。

| 步骤 | 操作 | 寄存器(地址) | 写入值 | 理由 |
|---|---|---|---|---|
| 1 | 上电稳定等待 | — | 延时 100ms | 器件上电 + 振荡器起振裕量（OSAL delay，任务态让出 CPU） |
| 2 | **读 WHO_AM_I (0x75)** | 读 | 期望 **0x68** | 链路连通 + 器件在位双重验证；≠0x68 返回 `MPU6050_STATUS_BAD_ID`，不再继续 |
| 3 | 器件复位 | PWR_MGMT_1 (0x6B) | 0x80 | `DEVICE_RESET=1`，所有寄存器恢复默认；该位硬件自动清零 |
| 4 | 复位后稳定 | — | 延时 100ms | 数据手册复位恢复时间 |
| 5 | 信号路径复位 | SIGNAL_PATH_RESET (0x68) | 0x07 | 清加速度/陀螺/温度数字路径 FIFO 状态 |
| 6 | 解除睡眠 + 选时钟 | PWR_MGMT_1 (0x6B) | 0x01 | `SLEEP=0`（退出默认睡眠态）、`CLKSEL=001`（X 轴陀螺 PLL，温度稳定性优于内部 RC） |
| 7 | 唤醒稳定 | — | 延时 30ms | PLL 锁定裕量 |
| 8 | DLPF 数字低通 | CONFIG (0x1A) | 0x03 | `DLPF_CFG=3`：陀螺 44Hz / 加速度 44Hz，兼顾噪声与响应（Register Map v4.2 §4.3） |
| 9 | 采样率分频 | SMPLRT_DIV (0x19) | 0x09 | `Fs = 1kHz/(1+9) = 100Hz`，与 100ms 采样周期匹配 |
| 10 | 陀螺量程 | GYRO_CONFIG (0x1B) | 0x00 | `FS_SEL=0` → ±250°/s，灵敏度 131 LSB/(°/s) |
| 11 | 加速度量程 | ACCEL_CONFIG (0x1C) | 0x00 | `AFS_SEL=0` → ±2g，灵敏度 16384 LSB/g |

> 修改量程：改 `mpu6050_config_t`（`gyro_fs_sel` 0-3 / `accel_afs_sel` 0-3），换算系数表见 §6.3；`cfg=NULL` 即用上表默认值。

## 6. 数据读取与换算

### 6.1 一次突发读 14 字节（0x3B 起）

```
主写:  S  0xD0  0x3B  →  重复起始 Sr
主读:  0xD1  [ax_H ax_L ay_H ay_L az_H az_L t_H t_L gx_H gx_L gy_H gy_L gz_H gz_L]  NACK  P
```

| 字节偏移 | 内容 | 寄存器 |
|---|---|---|
| 0–1 | 加速度 X（大端 int16） | ACCEL_XOUT_H/L (0x3B/0x3C) |
| 2–3 | 加速度 Y | 0x3D/0x3E |
| 4–5 | 加速度 Z | 0x3F/0x40 |
| 6–7 | 温度（大端 int16） | TEMP_OUT_H/L (0x41/0x42) |
| 8–9 | 陀螺 X | GYRO_XOUT_H/L (0x43/0x44) |
| 10–11 | 陀螺 Y | 0x45/0x46 |
| 12–13 | 陀螺 Z | 0x47/0x48 |

### 6.2 换算公式（实现：`mpu6050_raw_to_phy()`）

| 物理量 | 公式 | ±2g/±250°/s 下的系数 |
|---|---|---|
| 加速度 (g) | `raw / 2^15 × Range_g` | ÷ **16384** |
| 角速度 (°/s) | `raw / 32768 × Range_dps` | ÷ **131** |
| 温度 (℃) | `raw / 340 + 36.53` | —（Register Map §4.4，PLL 时钟下） |

量程系数对照：加速度 ±2/±4/±8/±16g → 16384/8192/4096/2048 LSB/g；陀螺 ±250/±500/±1000/±2000°/s → 131/65.5/32.8/16.4 LSB/(°/s)。

### 6.3 静止放置的预期读数（台账 V2–V4 判据）

- 重力轴 ≈ **±1.00g**（水平放置时 Z 轴 +1g 附近；允许 ±0.05g 静差）；
- 水平两轴 ≈ 0g（±0.02g 内）；
- 陀螺三轴 ≈ 0（零偏通常 ±1°/s 内，通电初期略大，属正常）；
- 温度 = 环境温度 + **3~5℃**（芯片自热，非故障）。

## 7. 错误处理与恢复

### 7.1 错误码表

| 错误码 | 触发条件 | 上层处置建议 |
|---|---|---|
| `MPU6050_STATUS_OK` | 成功 | — |
| `MPU6050_STATUS_PARAM` | NULL 指针 / 非法参数 | 检查实例化与入参 |
| `MPU6050_STATUS_NOT_INIT` | 未初始化先读 | 先走 instantiate |
| `MPU6050_STATUS_ERRORTIMEOUT` | SB/TXNE/RXNE/BUSY 超时 | 见 §7.2 恢复路径 |
| `MPU6050_STATUS_ERRORBUS` | 地址/数据 NACK、START 失败 | 检查接线/地址/上拉；见 §7.2 |
| `MPU6050_STATUS_BAD_ID` | WHO_AM_I ≠ 0x68 | 断电检查模块、AD0 电平、接线 |
| `err_count`（实例字段） | 累计通信错误数 | 台账追踪：`bsp_imu_get_stats()` |

### 7.2 三类故障的恢复路径

| 故障 | 检测点 | 自动恢复动作 | 残余风险与人工兜底 |
|---|---|---|---|
| **NACK**（器件无应答） | `pf_iic_wait_ack` 返回 0（AF 置位即清） | 重试 `retry_max`（默认 2）次，每次间隔 5ms | 仍失败→检查 AD0/接线/供电 |
| **通信超时** | 引擎等待循环耗尽（≈2–3ms 上限） | 同上重试；恢复路径与 NACK 相同 | 超时上限可调（`HW_IIC_EVT_LOOPS`） |
| **总线卡死**（从机拉死 SDA，BUSY 恒 1） | `hw_iic_start` 前置 BUSY 等待耗尽，或连续错误 | `hw_iic_bus_reset()`：外设软复位 → 引脚切 GPIO → **手动 9 个 SCL 脉冲 + STOP** → 重新 `hw_iic_init` | Handler 在重试全部失败后自动执行；仍失败则记录错误计数并等待下轮事件再恢复 |

驱动层设计保证：**任何一次读操作无论成败都会返回**（每个等待都有上限），不会忙等阻塞调度器；任务最长占用互斥锁时间 ≈ 重试总耗时（约 3×2–3ms + 5ms 退避 ≈ 15ms）。

## 8. FreeRTOS 集成

### 8.1 任务模型

| 任务 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|
| `send_imu_event`（生产者） | 1 | 256 字 | 100ms | 只投递采样事件，不碰 I2C |
| `imu_handler_thread`（消费者） | 3 | 512 字 | 事件驱动 | 互斥锁内完成 I2C 事务，读数回调 |

队列深度 10：生产快于消费时缓冲突发；`bsp_imu_read()` 投递超时 0（非阻塞，失败丢弃最旧策略可后续扩展）。

### 8.2 互斥锁（关键设计）

- `osal_mutex_t`（FreeRTOS `xSemaphoreCreateMutex` 包装，带优先级继承，无优先级反转）；
- 保护范围 = **整条 I2C 事务**（START…STOP），而非单个字节；
- 默认启用（即使当前独占总线），未来 AHT21 迁移到同一硬件 I2C 时**共用同一把锁实例**即可，两 Handler 地址不同（0x38/0x68）互不干扰；
- 锁等待超时 50ms，超时不死等。

### 8.3 lifetime 节流（对齐 AHT21 语义）

- 消费者按 `(now - last_tick) >= lifetime_ms` 判断（`>=`，规避 AHT21 曾出现的采样减半 bug）；
- **读失败不刷新 `last_tick`**，下一事件立即重试，不会拿旧值冒充新数据；
- 事件 `lifetime_ms=0` 表示无条件读取。

## 12. FAQ

**Q1：WHO_AM_I 读回 0x00 / 0xFF？**
接线或上拉问题。GY-521 板载 4.7k 上拉，正常无需外加；检查 SCL/SDA 是否接反、VCC 是否 3.3V（5V 经板载稳压也可，但逻辑电平仍 3.3V）。0x00 通常是 SDA 恒低（卡死），0x00/0xFF 同时出现多为未上电。

**Q2：WHO_AM_I 读回 0x98 / 0x70？**
0x98 = MPU9250/9255（九轴），0x70 = MPU6500。淘宝模块存在以 6500/9250 冒充 6050 的情况。本驱动寄存器协议对 6500/9250 的六轴部分**基本兼容**（温度公式不同：6500 为 raw/333.87+21），可改 `MPU6050_WHO_AM_I_VALUE` 与温度系数后使用，建议在台账记录实际器件 ID。

**Q3：AD0 悬空会怎样？**
AD0 内部有弱下拉，通常仍为 0x68；但线缆较长时可能漂移到 0x69。规范做法：AD0 直接接 GND。

**Q4：采样周期想改 200Hz？**
生产者任务延时改 5ms；`mpu6050_config_t.smplrt_div = 4`（1kHz/(1+4)=200Hz）；`lifetime_ms` 相应改 5。

**Q5：能输出姿态角吗？**
本版只交付原始六轴（见范围声明）。姿态解算（互补/卡尔曼/DMP）为上层算法，不在本次范围；需要时基于 `pf_read_data` 的 g/°/s 输出另行设计。

**Q6：和 AHT21 挂同一总线可以吗？**
可以：AHT21 目前走软件 I2C（PB13/14）。若迁移 AHT21 到硬件 I2C1，两器件地址不同（0x38/0x68），只需让两个 Handler 的 `osal_mutex_t` 指向**同一实例**，其余零改动。

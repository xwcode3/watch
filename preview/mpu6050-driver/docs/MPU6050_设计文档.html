MPU6050 桥接模式驱动设计文档

与 AHT21 驱动同一套桥接分层与契约风格，为 STM32F411CEU6 + FreeRTOS 平台实现基于标准外设库（SPL）硬件 I2C 的六轴传感器驱动：WHO_AM_I 先验、十步初始化、14 字节突发读、互斥锁保护、错误自动恢复。

平台：F411CEU6 · Cortex-M4F 总线：硬件 I2C1 · PB6/PB7 · 400kHz 器件：GY-521 · AD0=GND · 0x68 库：SPL 标准外设库（非 HAL） 编译：0 error · 0 warning
§1

架构总览

桥接模式两根轴：抽象轴（Handler 编排逻辑）与实现轴（驱动协议 + 总线引擎），通过 instantiate 时挂载的函数指针 ops 表解耦。

与 AHT21 驱动的一致性对照

维度AHT21（现有）MPU6050（本驱动）判定
驱动实例bsp_aht21_driver_t + pf_* ops 表bsp_mpu6050_driver_t + 同名 ops（增 pf_read_raw / pf_reset）同构
总线契约iic_driver_interface_t（iic_bus_t* 第一参数）同一契约头，iic_bus_t 扩展硬件外设字段同一套
Handler 线程temp_humi_handler_thread（队列+lifetime+回调）imu_handler_thread（同构）同构
错误码aht21_status_tmpu6050_status_t（同名风格 + ERRORBUS/BAD_ID）一致
Handler 耦合直接持有具体驱动类型（§6.5 债务）imu_ops_t + void* dev，具名适配函数修复债务
总线引擎软件位带 I2C（PB13/14）硬件 I2C 外设（I2C1）实现轴替换
§2

桥接接口定义

驱动层唯一认账的"实现"契约。返回约定：0 = 失败，非 0 = 成功（对齐软件 I2C 的 IICWaitAck 语义）。

槽位签名硬件引擎实现语义
pf_iic_init / deinitint32_t (iic_bus_t*)时钟+AF 引脚+外设复位+I2C_Init(400k)+Cmd
pf_iic_startint32_t (iic_bus_t*)GenerateSTART → 等 SB（BUSY 前置检查）
pf_iic_stopint32_t (iic_bus_t*)GenerateSTOP → 等 BUSY 清零 → 恢复 ACK
pf_iic_send_byteint32_t (iic_bus_t*, u8)SendData → 等 TXE
pf_iic_receive_byteint32_t (iic_bus_t*, u8*)等 RXNE → ReceiveData
pf_iic_wait_ackint32_t (iic_bus_t*)轮询 AF→NACK(0)；ADDR→读 SR1+SR2 清除→1；TXE→1；超时→0
pf_iic_send_ack / not_ackint32_t (iic_bus_t*)AcknowledgeConfig(ENABLE/DISABLE) 控制下一字节
pf_iic_bus_resetint32_t (iic_bus_t*)外设复位 → 引脚切 GPIO → 9×SCL 脉冲+STOP → 重新 init
为什么细粒度原语在硬件外设上成立：地址字节 ACK（ADDR 标志）与数据字节 ACK（TXE/BTF）在 wait_ack 内归一化；ADDR 的清除（读 SR1+SR2）对驱动层透明。读序列 receive(N-1) → send_not_ack → receive(N) → stop 在 400kHz（22.5µs/字节）下调用间隔远小于 1 字节时间，NACK 时序安全。
§3

硬件 I2C 配置

默认方案 A · I2C1

  • SCL=PB6，SDA=PB7（AF4，开漏+上拉，High Speed）
  • APB1 42MHz → 400kHz 快速模式，DutyCycle=2
  • GY-521：VCC→3V3 · SCL→PB6 · SDA→PB7 · AD0→GND · INT 悬空
  • 与 AHT21 软件总线 PB13/14 互不冲突

备选方案（引脚冲突时）

  • B · I2C2：PB10(SCL) / PB11(SDA) —— 仅改 iic_bus_mpu6050 一个结构体
  • C · I2C3：PA8(SCL) / PC9(SDA) —— 同上
  • 引擎时钟/复用映射自动分支，换总线零代码逻辑改动

SPL 初始化序列（hw_iic_init 内部执行）

RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOB, ENABLE);   /* 引脚端口 */
RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C1, ENABLE);    /* 外设      */
/* GPIO: AF4 + Open-Drain + Pull-Up + High Speed */
GPIO_PinAFConfig(GPIOB, GPIO_PinSource6, GPIO_AF_I2C1);
GPIO_PinAFConfig(GPIOB, GPIO_PinSource7, GPIO_AF_I2C1);
RCC_APB1PeriphResetCmd(RCC_APB1Periph_I2C1, ENABLE);    /* 外设软复位 */
RCC_APB1PeriphResetCmd(RCC_APB1Periph_I2C1, DISABLE);
I2C_InitTypeDef i = { .I2C_ClockSpeed = 400000, .I2C_Mode = I2C_Mode_I2C,
    .I2C_DutyCycle = I2C_DutyCycle_2, .I2C_OwnAddress1 = 0x00,
    .I2C_Ack = I2C_Ack_Enable, .I2C_AcknowledgedAddress = I2C_AcknowledgedAddress_7bit };
I2C_Init(I2C1, &i);  I2C_Cmd(I2C1, ENABLE);
I2C_AcknowledgeConfig(I2C1, ENABLE);
约束声明：全程使用 SPL（StdPeriph）函数，不使用 HAL、不依赖 CubeMX 生成代码。CubeMX 仅可作引脚冲突人工核对工具（PB6→I2C1_SCL、PB7→I2C1_SDA，检查绿色冲突标记后不要生成代码进 SPL 工程）。

初始化序列（逐条寄存器说明）

实现于 mpu6050_init_impl()。默认 ±2g / ±250°/s / DLPF 44Hz / Fs=100Hz。寄存器依据：RM-MPU-6000A v4.2。

#操作寄存器(地址)写入值理由
1上电稳定等待—100msOSAL 任务态延时（非忙等，规避 AHT21 的 TIM2 忙等债务）
2读 WHO_AM_I0x75（读）期望 0x68链路连通 + 器件在位双重验证；≠0x68 → MPU6050_STATUS_BAD_ID，终止
3器件复位PWR_MGMT_1 (0x6B)0x80DEVICE_RESET=1，寄存器恢复默认；位硬件自动清零
4复位后稳定—100ms数据手册恢复时间
5信号路径复位SIGNAL_PATH_RESET (0x68)0x07清加速度/陀螺/温度数字路径
6唤醒 + 选时钟PWR_MGMT_1 (0x6B)0x01SLEEP=0；CLKSEL=001 → X 轴陀螺 PLL（温漂优于内部 RC）
7PLL 锁定等待—30ms唤醒裕量
8DLPF 低通CONFIG (0x1A)0x03DLPF_CFG=3 → 陀螺 44Hz / 加速度 44Hz，噪声与响应折中
9采样率分频SMPLRT_DIV (0x19)0x09Fs = 1kHz/(1+9) = 100Hz，匹配 100ms 采样周期
10陀螺量程GYRO_CONFIG (0x1B)0x00FS_SEL=0 → ±250°/s（131 LSB/°/s）
11加速度量程ACCEL_CONFIG (0x1C)0x00AFS_SEL=0 → ±2g（16384 LSB/g）
§5

六轴数据读取与换算

主写:  S  0xD0  0x3B        → 重复起始 Sr
主读:  0xD1  [ax_H ax_L ay_H ay_L az_H az_L t_H t_L gx_H gx_L gy_H gy_L gz_H gz_L] NACK P

换算公式（mpu6050_raw_to_phy）

  • 加速度(g) = raw ÷ 16384（±2g 档）
  • 角速度(°/s) = raw ÷ 131（±250 档）
  • 温度(℃) = raw ÷ 340 + 36.53
  • ±4/8/16g → 8192/4096/2048；±500/1000/2000 → 65.5/32.8/16.4

静止放置判据（台账 V2–V4）

  • 重力轴 ≈ ±1.00g（±0.05g 静差内）
  • 水平两轴 |g| ≤ 0.02
  • 陀螺三轴 |dps| ≤ 1.5（上电初期 2.0）
  • 温度 = 环境 +3~5℃（芯片自热，非故障）
§6

错误处理与恢复

错误码触发处置
OK=0成功—
PARAMNULL/非法参数检查实例化与入参
NOT_INIT未初始化先读先走 instantiate
ERRORTIMEOUTSB/RXNE/BUSY 等待耗尽（≤2-3ms）重试×2 → 总线复位
ERRORBUS地址/数据 NACK（AF 即时清除）重试×2 → 总线复位；查接线/AD0
BAD_IDWHO_AM_I ≠ 0x68断电查模块/AD0/接线（0x98=9250、0x70=6500，见 FAQ）

保证：任何读操作必返回（等待均有上限），不会忙等阻塞调度器；任务最长持锁 ≈ 重试总耗时（约 15ms）。互斥锁为 FreeRTOS 互斥量（优先级继承），锁等待超时 50ms；连续失败由 Handler 自动执行 hw_iic_bus_reset → pf_reset → 重 init 自愈。

§7

FreeRTOS 集成与移植步骤

任务与同步

  • 生产者 prio1/栈256：100ms 投事件，不碰 I2C
  • 消费者 prio3/栈512：queue_get 阻塞 + lifetime(≥) 节流
  • 队列深 10；失败不刷新 last_tick，下事件即重试
  • 互斥锁整事务保护（优先级继承，50ms 超时）
  • AHT21 迁入同总线时：共用同一把锁实例即可

十步移植（约 15 分钟）

  1. 拷贝 Core/Src（iic_interface.h, hw_iic.*）+ BSP/MPU6050/ + OSAL 契约头 + 集成示例
  2. 3 个 .c 加入工程编译，include 路径加 BSP/MPU6050
  3. OSAL 合并：有现成 osal_freertos.c 则删示例内置包装段
  4. （可选）定义 MPU6050_USE_ELOG 接 EasyLogger
  5. 接线 3V3/GND/PB6/PB7/AD0→GND
  6. main() 调 mpu6050_app_task_create()
  7. 上电看 [IMU] 输出；异常按错误码表定位
  8. 按测试台账 V1–V6 回填数据

FAQ要点
WHO_AM_I = 0x00/0xFF？接线/上拉/供电问题；0x00 常为 SDA 卡死（驱动会自动走 bus_reset）
WHO_AM_I = 0x98 / 0x70？模块实为 MPU9250(0x98)/MPU6500(0x70)；六轴协议基本兼容，改 WHO_AM_I 值与温度系数（6500: raw/333.87+21）即可，务必记入台账
想改 200Hz？生产者延时 5ms + smplrt_div=4 + lifetime_ms=5
要姿态角？本次仅原始六轴（范围声明）；融合算法基于 pf_read_data 的 g/°/s 另行设计

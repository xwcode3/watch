# 手表 App 项目——架构与调用逻辑说明文档

> 适用对象：需要接手维护 / 二次开发本项目的人
> 代码基线：STM32F411CEU6 + StdPeriph 标准库 + FreeRTOS + 自研 Ymodem OTA
> 阅读约定：本文只描述**实际参与编译并被调用**的逻辑；明确标注的"未启用代码"不在主流程内。

---

## 1. 系统总览

| 项 | 内容 |
|----|------|
| MCU | STM32F411CEU6（Cortex-M4，FPU，512KB Flash / 128KB RAM） |
| 时钟 | HSE 25MHz → PLL → **SYSCLK 100MHz**（HCLK=100，PCLK1=50，PCLK2=100） |
| 库 | STM32F4xx **Standard Peripheral Library**（非 HAL/LL） |
| RTOS | FreeRTOS V202212.01（抢占式，tick=1ms，5 个优先级） |
| 构建 | CMake + arm-none-eabi-gcc（由 STM32CubeMX 生成的 `cmake/stm32cubemx/CMakeLists.txt` 组织源码） |
| 日志 | EasyLogger（异步）+ SEGGER RTT（printf 重定向到 USART1） |
| 外部器件 | W25Q64（SPI 外部 Flash，存 OTA 升级包）、AT24C02（I2C EEPROM，存 OTA 状态/App 长度） |
| 关键 GPIO | PC13=LED，PA0=KEY，PA4=W25Q64 CS，PA5/6/7=SPI1，PA9/10=USART1 |

## 3. Flash 分区与启动流程

### 3.1 地址映射（重要：当前代码存在不一致，见第 8 节）

- 链接脚本 `STM32F411XX_FLASH.ld`：`FLASH ORIGIN = 0x08010000, LENGTH = 448K`
  → **APP 被链接到 0x08010000**，占用 0x08010000 ~ 0x08080000。
- `main.c`：`SCB->VTOR = FLASH_BASE | 0x10000`（= 0x08010000），与链接脚本一致。
- `boot_manager.h`：`ApplicationAddress_boot = 0x08008000`，`BackupApplicationAddress_boot = 0x08020000`
  → Bootloader 视角认为 App 在 **0x08008000**，备份区在 0x08020000。

两者对"App 运行地址"的认知不同（0x08010000 vs 0x08008000），是本项目最大的隐患点。

### 3.2 启动顺序（main 调用链）

```
Reset_Handler
  └─ main()
       ├─ app_pre()               // VTOR=0x08010000; __enable_irq()
       ├─ SystemClock_Config()    // HSE→PLL→100MHz; SysTick=1ms
       ├─ gpio_init()
       ├─ ota_usart1_config()     // USART1@115200 + DMA Rx + IDLE 中断; 同时是 printf 输出口
       ├─ get_clock_info()        // 打印时钟树
       ├─ easylogger_config()     // 日志格式化/启动
       ├─ ee_CheckOk()            // 探测 AT24C02 是否在位
       ├─ spi1_init()             // SPI1 初始化(驱动 W25Q64)
       ├─ W25Q64_Init()
       ├─ ee_ReadBytes(&e_ota_state, 0x00, 1)   // 读 OTA 状态字
       │
       ├─ [OTA 上电自检] ──────────────────────────────┐
       │    if (== OTA_STATE_APP_FIRST_CHECKING 0x44)   │
       │        → 写回 NO_APP_UPDATE，while(1) 等 BL 看门狗复位
       │    else if (!= NO_APP_UPDATE 0x00)              │
       │        → SoftReset() 主动复位                   │
       └────────────────────────────────────────────────┘
       ├─ app_task_create()       // 创建 led_blink_task(优先级1) + ota_task(优先级2)
       └─ vTaskStartScheduler()
```

**OTA 状态字（存于 EEPROM 0x00）：**
`0x00 NO_APP_UPDATE` / `0x11 DOWNLOADING` / `0x22 DOWNLOAD_COMPLETE` / `0x33 FIRST_CHECK_START` / `0x44 FIRST_CHECKING` / `0x55 NEED_UPDATE`。
App 正常启动要求状态字 == `0x00`，否则会 SoftReset 交还给 Bootloader 处理（Bootloader 再决定跳转或重新升级）。

## 4. 运行期任务

`app_task_create()` 实际只创建 2 个任务：

| 任务 | 优先级 | 栈(words) | 职责 |
|------|--------|-----------|------|
| `led_blink_task` | 1 | 128 (512B) | 每 2s 翻转 PC13（指示灯/心跳） |
| `ota_task` | 2 | 256 (1KB) | OTA 状态机：等待命令→下载→等待更新→按键确认复位 |

> 优先级数字越小越高（FreeRTOS：0 最高）。本工程 `configMAX_PRIORITIES=5`，空闲任务/定时器任务在更低优先级。
> 其余"框架任务"（key/usart/dma/adc）均未创建，不影响运行。

### 4.1 `led_blink_task`（最简形态）
```
while(1){ GPIO_ToggleBits(PC13); vTaskDelay(2000); }
```
纯心跳灯。LED/KEY 那套事件框架（`bsp_led_handler.c`）在本工程未挂载。

## 5. OTA 状态机（核心业务）

`ota_task()` 是一个 `for(;;)` + `switch` 状态机（枚举 `E_Ota_State`）：

```
WaitReqDownload ──收到 0x11 0x22 0x33──▶ OtaDownload
                                            │ (Ymodem 收完且 size>0)
                                            ▼
                                      WaitReqUpdate ──收到 0x55 0x66 0x77──▶ OtaEnd
                                                                                │
                                                                      按键(20s内)│
                                                                                ▼
                                                                          SoftReset()
```

- **WaitReqDownload**：`uartx_receive2idle_dma(USART1,s_au8_OtaCmd,4)` 武装"一次性 DMA+IDLE"收 4 字节命令；随后 `xQueueReceive(Q_YmodemReclength,...,portMAX_DELAY)` 阻塞等 IDLE 中断把"收到长度"放入队列。校验 3 字节 == `11 22 33` 后写 EEPROM=0x11，进入 OtaDownload。
- **OtaDownload**：`YmodemUart_EnterRxMode()` 关 DMA/IDLE，切"轮询 DR"模式；`Ymodem_Receive_2buffer(A,B)` 真正收包并**直接写 W25Q64**；收完 `YmodemUart_RestoreDmaMode()` 恢复命令接收。成功后回 ACK，把 `0x22` 和 **App 长度**（4 字节）写 EEPROM，进入 WaitReqUpdate。
- **WaitReqUpdate**：再次等命令 `55 66 77`，进入 OtaEnd。
- **OtaEnd**：`ota_key_scan()` 在 ~20s 内检测 PA0 按下 → `SoftReset()`（交还给 Bootloader 完成"外部 Flash→内部 Flash 的解密搬运 + 跳转"）。

> 升级包的**落地**不在 App：App 只负责把密文固件收进 **W25Q64 外部 Flash**。真正的"解密 + 写入内部 Flash + 跳转"由 Bootloader 的 `copy_app_to_executable()` / `JumpToApp1()` 完成（代码在 `boot_manager.c`，属于另一个工程）。

## 6. 关键模块调用关系

### 6.1 串口命令接收（DMA + 空闲线）
- `ota_usart1_config()`：USART1@115200，开 `USART_IT_IDLE`，开 `USART_DMACmd(Rx)`，`DMA2_Stream2`（Normal 模式）把数据搬进命令缓冲。
- `USART1_IRQHandler()`（ISR）：RXNE 做回显；**IDLE** 时先读 SR+DR 清标志，再算 `rec_len = dma2_init_ndtr - DMA_GetCurrDataCounter(DMA2_Stream2)`，用 `xQueueSendFromISR(Q_YmodemReclength,&rec_len,0)` 通知 `ota_task`。
- `uartx_receive2idle_dma()`：重新武装下一次"一次性 DMA 收 N 字节"。
- 切换到 Ymodem 下载时 `YmodemUart_EnterRxMode()` 必须关掉 DMA 与 IDLE，否则 DMA 与 Ymodem 轮询 `SerialKeyPressed()` 抢同一个 DR，且 IDLE 会误触发命令队列。

### 6.2 Ymodem 下载 → W25Q64
`Ymodem_Receive_2buffer(buf1,buf2)`（轮询模式，逐字节 `SerialKeyPressed`）：
1. 收 SOH(128B)/STX(1K) 包，校验包序号补码、XMODEM-CRC16（`crc_xmodem`）。
2. 第 0 包是文件名包：解析出文件名与**文件大小 size**。
3. 数据包含 `PACKET_HEADER` 偏移后调用 `W25Q64_WriteData(payload, packet_length)` 写入外部 Flash；双缓冲 `buf1/buf2` 交替接收。
4. 收完 `W25Q64_WriteData_End()` 把不足一个扇区的尾巴刷入 Flash。
返回 `size` 给 `ota_task` 写 EEPROM。

### 6.3 W25Q64 扇区缓冲封装（`bsp_w25qxx_handler`）
- `W25Q64_WriteData()`：数据先填 4096B `databuf`，满一个 SUBSECTOR(4KB) 就 `W25Qx_Erase_Block` + 按 PAGE(256B) 分 16 次 `W25Qx_Write`。累计 `write_index` 记录总字节数。
- `W25Q64_ReadData()`：按 4KB 扇区回读（供 Bootloader `copy_app_to_executable` 用），靠 `write_index/read_index` 判断是否读完。

### 6.4 解密搬运（Bootloader 侧，`boot_manager.c`）
- `copy_app_to_executable()`：从 W25Q64 读 16B 头（经 `Aes_IV_key256bit_Decode` 解出 App 长度）→ 擦内部 Flash → 逐 16B 读密文、AES 解密、按 4B 写内部 Flash。
- `Aes_IV_key256bit_Decode()`：自研 **AES-256-CBC**（IV 链式：解密后与 IV 异或，再把原密文存回 IV），密钥/IV 当前为硬编码测试值（`0x31 0x32 ...` = ASCII "1212..."）。
- `JumpToApp1()`：校验栈顶在 SRAM、`NVIC_SetVectorTable(FLASH,0x8000)`、关 SysTick 中断、清 RCC、置 MSP、跳复位向量。

### 6.5 内部 Flash 操作（`flash.c`）
- `flash_erase(addr,size)`：按地址算起止扇区，擦除区间内的扇区（`VoltageRange_3`）。
- `flash_write(addr,data)`：`FLASH_Unlock → FLASH_ProgramWord → FLASH_Lock`，每次 4 字节。
- 供 Bootloader 解密搬运时把固件写进内部 Flash。

### 6.6 EEPROM（状态/长度持久化）
`ee_ReadBytes/ee_WriteBytes` 走 I2C（`iic.c` 的 `i2c_Start/SendByte/WaitAck/...`），AT24C02 页写，写后轮询 ACK 等内部写完成。OTA 状态字存 0x00，App 长度存 0x01（4 字节）。

### 6.7 SPI / I2C 驱动
- SPI1：PA5/6/7，CS=PA4，模式 `CPOL=Low/CPHA=1Edge`(Mode0)，**预分频 256**（≈390kHz），软件 NSS。全双工 `spi1_read_write_byte` 收发同步。
- I2C：标准 GPIO 位bang 或外设（由 `iic.c` 提供 `i2c_*` 原语），EEPROM 用。

## 7. 中断与 RTOS 协作

- `USART1_IRQn`：抢占优先级 **5**；在 ISR 里用 `xQueueSendFromISR` + `portYIELD_FROM_ISR` 唤醒 `ota_task`。
- `DMA2_Stream0_IRQHandler`（在 `FreeRTOS_tasks.c`，属于未启用的 ADC/DMA 框架）：用 `xTaskNotifyFromISR` + `portYIELD_FROM_ISR` 示范了正确的 ISR→任务通知写法。
- `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5`：优先级数值 **≤5** 的 ISR 可安全调用 FreeRTOS "FromISR" API；>5 的 ISR 不能调用。USART1(5) 合规。
- 注意：`EXTI0_IRQHandler`（KEY 框架，未启用）里调用了 `xTaskGetTickCount()`——**这是错误用法**，ISR 内应使用 `xTaskGetTickCountFromISR()`。

## 8. 已知问题 / 坑（维护必读）

1. **App 运行地址不一致**：链接脚本/VTOR=0x08010000，而 `boot_manager.h` 的 `ApplicationAddress_boot=0x08008000`。若 Bootloader 按 0x08008000 跳转，会跳进错误区域。**两工程必须对齐地址表**（建议统一成 0x08010000，并相应调整 Bootloader 自身占用与备份区）。
2. **`flash_erase()` 数组越界**：`for(i=0; i<=12; i++)` 访问 `Flash_Sectorsize[12]`，但该数组只有 12 项（0~11），属于**越界读**（UB），可能误擦多余扇区。应改为 `i < 12` 或 `i < FLASH_SECTOR_NUM`。
3. **栈溢出检测关闭**：`configCHECK_FOR_STACK_OVERFLOW = 0`；`ota_task` 栈仅 256 words，且内部有 1030B 的 `g_au8_YmodemRec_A/B` 缓冲（静态，不占栈）。生产建议开启 `=2` + 提供 `vApplicationStackOverflowHook`，并用 `uxTaskGetStackHighWaterMark` 实测。
4. **`configASSERT` 是死循环**：`if(x==0){taskDISABLE_INTERRUPTS();for(;;);}`——断言失败直接锁死，现场用 RTT/串口看死前日志。
5. **Bootloader 函数编进 App 却不用**：`boot_manager.c` 的 `JumpToApp1/back_to_app/copy_app_to_executable` 在 App 工程里编译但不调用，且 `back_to_app` 读的是 `BackupApplicationAddress_boot(0x08020000)`，与当前"下载到 W25Q64"的实际路径不一致——属于旧设计残留，建议挪回 Bootloader 工程或删除。
6. **AES 密钥/IV 硬编码为测试值**：生产需改为可配置/烧录，并增加固件签名验签（仅 AES 加密不能防篡改）。
7. **`printf` 进中断/任务**：`USART1_IRQHandler` 里有 `printf` 回显（`USART_SendData` 轮询），高波特率下会拖慢 ISR；正式版应去掉或仅留 RTT。
8. **`DownloadAppData_task` 未启用**：当前 Ymodem 引擎**阻塞式**直接写 W25Q64（在 `ota_task` 上下文里跑 Ymodem 轮询），若后续想让下载不阻塞 OTA 命令响应，应恢复"双缓冲→队列→消费者任务写 Flash"的设计。

## 9. 一句话数据流总结

```
[服务器/PC] --Ymodem(USART1, 轮询)--> ota_task --W25Q64_WriteData--> W25Q64(外部Flash,密文)
                                        │(EEPROM 记 0x22 + size)
[按键] --> SoftReset() --> Bootloader
Bootloader: copy_app_to_executable() 读 W25Q64 --AES-256-CBC 解密--> 内部Flash(0x08010000) --> JumpToApp1()
```

> 维护要点：改地址先对齐 Bootloader 与 App 两份映射；动 Flash 擦写先确认扇区范围；OTA 状态字是 App 与 Bootloader 之间的"契约"，任何一方改动都要同步。

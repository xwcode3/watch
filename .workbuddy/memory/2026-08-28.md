# 2026-08-28

## preview/mpu6050-driver 代码评审（只读，未改代码）

评审对象：`preview/mpu6050-driver/`（集成层 + handler + driver + hw_iic 引擎 + 自带 osal/iic 契约头）。

### 关键结论
- **合进去大概率一次跑不通**，三处阻塞点全在 `Core/Src/hw_iic.c`：
  1. `hw_iic_start()` 开头死等 `BUSY==0`，而重复起始（repeated START）时主机仍占总线 →
     `mpu6050_read_regs` 相位 2 必然超时 → 连 init 里的 WHO_AM_I 都读不到，instantiate 直接失败。
     必须区分 `start` 与 `repeated_start`（后者只等 SB，不等 BUSY）。
  2. `hw_iic_wait_ack()` 用 TXE 置位冒充 ACK：地址字节写进 DR 后 TXE 会先于 ADDR 置位，
     于是瞬间返回 1，NACK/AF 检测形同虚设。地址阶段应等 ADDR|AF，数据阶段应等 BTF|AF。
  3. `hw_iic_gpio_config()` 只 `GPIO_Init` 了 SCL（`g.GPIO_Pin = scl_pin`），SDA 仅做了
     `GPIO_PinAFConfig` → PB7 从未配成 AF 开漏，硬件 I2C 无输出。
- **契约与工程现有 System/OSAL/osal.h 不兼容**（最容易被忽略的坑）：
  - `get_tick_ms` 工程签名 `osal_status_t (*)(uint32_t *ms)`，preview 是 `uint32_t (*)(void)`。
  - `osal_status_t` 重复定义且取值不同（OSAL_OK=0/RESERVED=0xFF vs 0x7FFFFFFF）。
  - `osal_queue_t` 少了 `queue_delete`；工程实例是 `const`，preview 接口收非 const 指针。
  - 工程无 `osal_mutex_t`，需补 osal_freertos 实现，否则只能传 NULL。
- **类型重名**：preview 的 `iic_bus_t` 撞 `Core/Inc/iic.h`；`iic_driver_interface_t` 撞
  `BSP/AHT21/bsp_aht21_driver.h`（AHT21 版字段签名完全不同）。同 TU 共 include 必报错。
- 头文件 guard `__BSP_MPU6050_DRIVER_H` 等双下划线 → 违反工程约定（`BSP_<MODULE>_H` + `#pragma once`），
  且是 C 保留标识符；`__mount_handler`/`__mount_callback` 同理。
- 其它：`hw_iic.c` 用 GCC 内建 `__builtin_ctz`（armcc 兼容存疑）；`mpu6050_raw_to_phy` 换算常量写死
  16384/131，cfg 改量程后数据全错；handler 里 `static driver_obj` 实为单例（与"per-instance"宣传矛盾）；
  恢复路径 `pf_init(dev, NULL)` 会丢用户 cfg；`SIGNAL_PATH_RESET` 后未等待。

## 新增：环形缓冲中间件（参考 mid_circular_buffer 重写）

- 位置：`preview/mpu6050-driver/middleware/ringbuf/mid_ringbuf.{h,c}` + 文档 `docs/环形缓冲中间件设计说明.md`。
- 设计（**v3 定稿**）：原 `BSP/USART/mid_circular_buffer` 字节环形思路升级版——**外部存储传入（零 heap）、
  零 elog 依赖、由 head/tail 推导长度 + 牺牲一槽判满（owner 明确要求：不用 count）、
  容量 2 的幂用 `& mask` 回绕、批量 write/read（一次塞整帧 14 字节）、可选锁钩子 pf_lock/pf_unlock、
  reject/overwrite 策略可选、DMA 零拷贝路径（begin/commit/abort + dma_active 混用保护）**。
- **v3 关键收益与约束**：生产者只写 head、消费者只写 tail → **reject + SPSC 可完全无锁**
  （配 `RINGBUF_BARRIER()` 编译器屏障）；**overwrite 模式会推进 tail，必须加锁**。可用容量 = cap-1。
- 验证：gcc -Wall -Wextra 0 warning；本地逻辑自测 60+ 断言（容量语义/写满被拒/overwrite 保最新/
  200 次回绕/无锁 SPSC/set_lock 成对/无效实例/DMA 预留提交回滚/回绕分段/peek 不消费）ALL_TESTS_PASS。
- 未改动 app 任何原有文件。

### 自复查发现的问题（已出改动清单，待 owner 逐条确认后再改）
- **P0 真 bug**：`ringbuf_pop` 的 `count==0` 判空在加锁**之外**（.c:151 vs 155），TOCTOU →
  并发下 `count--` 下溢成 0xFFFFFFFF，之后 read 会疯狂读越界。判空必须移进锁内。
- **P1 死锁风险**：`ringbuf_set_lock` 允许只设 lock 不设 unlock → lock 后永不 unlock。应校验成对。
- **P1**：`ringbuf_peek` 未加锁，注释却写"无需加锁可安全预览"——并发写(尤其 overwrite)下会读到撕裂数据。
- **P2**：`is_full(NULL)` 与未 init(cap=0,count=0) 都返回 true，与 is_empty 同时为真，掩盖未初始化错误。
- **P2 设计缺口**：缺 DMA/ISR 友好的"预留+提交"接口。原 `mid_circular_buffer` 有
  `get_head_pos + head_pos_increment`，正是给 USART DMA+IDLE 用的；旧版 BSP/MPU6050 驱动有
  `pf_iic_mem_read_dma`，将来走 DMA/INT 中断接收就没有零拷贝入口。需补 `get_write_ptr + commit(n)`。
- **P3 文档与实现不一致**：`mid_ringbuf.c` 头部注释仍写"牺牲一槽/最多 cap-1"，但实现是
  count==cap 判满、可用满 cap（上次只改了 .md，漏改 .c）。
- **P3 规范**：头文件只有 `#ifndef MID_RINGBUF_H`，缺工程约定的 `#pragma once`。
- **P3**：`ringbuf_write` 整段持锁逐字节拷贝，若 pf_lock 是临界区(关中断)且 len 大会长时间关中断。

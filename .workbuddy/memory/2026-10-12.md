## 链接失败：3 类符号未定义（源文件本身编译零告警）
1. **15 个 `I2C_*` 未定义** ← 主因：`cmake/stm32cubemx/CMakeLists.txt` 的 `STD_PERIPH_Src`(133-145 行)
   漏了 `Drivers/STM32F4xx_StdPeriph_Driver/src/stm32f4xx_i2c.c`。文件在磁盘上存在，只是没进构建。
   引用方 `Core/Src/iic.c`（MPU6050 走 I2C2 硬件 I2C）。
2. **`mpu6050_handler` 未定义** ← 名字对不上：
   `Core/Src/FreeRTOS_tasks.c:374` 用 `extern bsp_mpuxxx_handler_t mpu6050_handler;`（384/385 行使用），
   而 `BSP/MPU6050/bsp_mpu6050_handler.c:11` 实际定义的是 `handler_instance`。
3. **`pf_pin_interrupt_callback` / `pf_dma_interrupt_callback` 未定义** ←
   `bsp_mpu6050_handler.c:17-18` 只有 `extern` 声明 + 27/36 行赋值，全工程无定义。
   设计意图：driver 的 `bsp_mpuxxx_driver_inst()` 末尾调 `callback_register(int_interrupt_callback)`
   / `callback_register_dma(dma_interrupt_callback)`，即 handler 的 `register_callback*` 把驱动 ISR 入口
   存进这两个全局指针，供中断服务函数调用 —— "存到哪儿"这步没实现。

## 链接修好后仍必炸的运行期断点（同一批工作的一半）
- **A. `DMA1_Stream2_IRQHandler` 不存在**（`iic.c:1085/1131` 注释明确点名"本文件第 2 节"，但 iic.c 到
  1283 行结束也没这个函数）。而 `iic_mem_read_dma()` 已经在 1173-1177 行使能 `DMA1_Stream2_IRQn`(prio5)、
  1209 行使能 TC/TE → DMA 一完成就跳 weak `Default_Handler` 的 `b Infinite_Loop` 死循环。
- **B. MPU6050 INT 引脚 EXTI 完全没配**：`iic.h:115-116` 注释声称"PB5 上的 MPU6050 INT 外部中断配置"，
  实际无 PB5 GPIO/EXTI/NVIC 初始化、无 `EXTI9_5_IRQHandler`。而 INT 回调是 DMA 读的唯一发起者。
- **C. 数据链路自洽性核对**（用来判断"修到哪一步能看到数据"）：
  INT → `int_interrupt_callback` 启 DMA → DMA TC → `dma_interrupt_callback`（里面 `#if 0` 掉了队列/信号量，
  只留 `circular_buf.pf_data_writed()` + 1512 行 `g_is_dma_readed = 1`）→ handler 线程轮询
  `mpuxxx_flag_read()` → 投 unpack 队列 → unpack_task 解析。**A/B 两处是这条链的两头，都断着。**
- **D. driver 实例建在任务栈上**：`bsp_mpu6050_handler.c:259/261` 局部 `bsp_mpuxxx_driver_t p_driver;`
  再 `handler_instance.p_driver = &p_driver;`，任务栈 1024 words(4KB)，且 `configCHECK_FOR_STACK_OVERFLOW=0`。
- **E. 死成员**：`bsp_mpu6050_driver.h:132-133` 的 `pf_dma_completed_callback` / `pf_int_interrupt_callback`
  从未被赋值，易误导后来者以为中断已接好。
- **F. `mpuxxx_handler_init()` 无头文件原型**（可加 static）。

# 2026-08-25

## 产出：软件 IIC 通信时序规范文档

- 新增 `docs/软件IIC通信时序规范.md`（只总结、未改任何代码）。
- 背景：AHT21 已跑通读温湿度，用户踩坑点是软件 IIC 时序"不同阶段相互影响/歧义"。
- 核心发现：`Core/Src/iic.c` 里**并排两套软件 IIC**——
  - 小写 `i2c_*`（EEPROM/AT24CXX 用，宏 `EEPROM_I2C_*` PB8/PB9，方式A：全程开漏输出+读IDR），收尾规范（每阶段 SCL=0、SDA=1）。
  - 大写 `IIC*`（AHT21 用，`iic_bus_t`+`SDA_Input/Output_Mode` 方向切换，方式B）。
- 大写套件隐患（已标注、未改）：`IICSendByte`/`IICWaitAck`/`IICReceiveByte`/`IICSendAck` 退出时 SDA 未回到"释放(高)"——`SDA_Output_Mode` 只改方向不清/置 ODR，SDA 残留上一字节 bit0 电平。当前 AHT21 能跑通是**靠调用顺序碰巧覆盖**，不是靠原语契约。
- 语义歧义：小写 `i2c_WaitAck` 返回 0=ACK/1=NACK；大写 `IICWaitAck` 返回 0=NACK/1=ACK，两套相反（bsp_aht21_driver.c 有注释纠正）。
- 文档主体 = 三条根本规则 + 各阶段标准时序 + 收尾契约总表 + 对照代码分析 + Checklist + 参考模板（伪代码，未落地）。
- 收尾契约口诀：SDA 只在 SCL 低时变（除 START/STOP）；每个原语退出 SCL=0、SDA=释放(高)；方向切换在 SCL 低时做且切完立即置高。
- 补充「大厂正规做法」章节（同文档第十节）：最权威参考=Linux 内核 i2c-algo-bit.c（4回调抽象 + sclhi 读回检测时钟拉伸/超时 + 原语 assert 前置状态 + 可配置 udelay）；另引 ST 官方（开漏+外部上拉、上拉选型公式）、ESP-IDF（10ms 超时、9时钟总线恢复）、WCH 软 I2C（SDA 输出/输入动态切换）。
- 本工程相对大厂的 4 个差距（按价值排序）：①无时钟拉伸检测 ②无总线恢复 ③原语无前置 assert ④无重复起始 Sr。

# 2026-08-09

## BSP 层头文件 include guard 统一重构
- 将 BSP 下全部 14 个 `.h` 的 guard 统一为 `#pragma once` + `BSP_<模块>_H` 传统 guard 组合。
- 原风格三种混用：`__BSP_LED_DRIVER_H__`(双下划线,reserved)、`_BSP_ADC_H_`(单下划线+大写,reserved)、
  `WATCH_BSP_AT24CXX_DRIVER_H`。全部改为 `BSP_LED_DRIVER_H` / `BSP_ADC_H` / `BSP_AT24CXX_DRIVER_H` 等。
- 同时修正了结尾 `#endif` 注释（如 `#endif /* BSP_LED_HANDLER_H */`）。
- 校验：无残留旧风格、14 ifndef ↔ 14 define 配对、每文件恰 1 个 `#pragma once`。
- 根因讨论：跨驱动重复宏（如 `OS_SUPPORTING` 定义于 3 处、`DEBUG` 在 LED driver 启用但 handler 注释掉），
  后续可进一步抽 `bsp_config.h` 收口 feature flags；本次未做，待用户决定。
- 约定已写入 MEMORY.md 的"必记约定 / 坑"。

## osal 抽象层新增 osal_yield_t
- 在 `System/OSAL/osal.h` 新增接口结构体 `osal_yield_t { osal_status_t (*yield)(void); }`，
  对齐既有 `osal_delay_t`/`osal_critical_t` 等"函数指针结构体"模式（统一返回 `osal_status_t`）。
- 在 `System/OSAL/osal_freertos.c` 实现 `static osal_status_t osal_freertos_yield(void)`，
  内部调 FreeRTOS `taskYIELD()`，返回 `OSAL_OK`；并提供全局实例
  `const osal_yield_t osal_yield_freertos = { osal_freertos_yield };`。
- 在 `System/OSAL/osal_freertos.h` 增加 `extern const osal_yield_t osal_yield_freertos;` 声明。
- 注意：`taskYIELD()` 仅限任务上下文，绝不可在 ISR 中调用（ISR 应走 `portYIELD_FROM_ISR`）。
- 尚未把 `osal_yield_freertos` 接入任何 BSP 驱动的实例化流程，仅完成抽象层定义。

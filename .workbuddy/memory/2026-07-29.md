# 2026-07-29

## 通读手表 App 项目并产出两份文档
- MCU: STM32F411CEU6 (Cortex-M4, 512KB/128KB)。库: STM32F4 StdPeriph（非 HAL）。
  RTOS: FreeRTOS V202212.01 (抢占, tick=1ms, 5 优先级, heap_4, 总堆 75KB)。
- 构建: CMake + arm-none-eabi-gcc，源码组织见 `cmake/stm32cubemx/CMakeLists.txt`。
- 实际运行任务仅 2 个: `led_blink_task`(prio1, 翻转 PC13)、`ota_task`(prio2, OTA 状态机)。
  其余 LED/KEY 框架、ADC/DMA、USART 解析任务都是未启用的死代码（仅在框架探索期写过）。
- OTA 主路径: `ota_task` 等命令 11 22 33 → `Ymodem_Receive_2buffer` 把密文固件写
  W25Q64 外部 Flash → 状态/长度写 AT24C02 EEPROM → 按键 `SoftReset()` 交还 Bootloader。
  Bootloader 侧 `copy_app_to_executable`(boot_manager.c) 从 W25Q64 读、AES-256-CBC 解密、写内部 Flash、`JumpToApp1` 跳转。
- 外设: SPI1(PA5/6/7, CS PA4, Mode0, 预分频256≈390kHz) 驱动 W25Q64；I2C 走 AT24C02 EEPROM。
  USART1@115200 + DMA2_Stream2(Normal) + IDLE 中断收 OTA 命令。AES 自研 AES-256-CBC，Key/IV 硬编码测试值。
- 产出文档:
  - `docs/架构与调用逻辑说明.md`
  - `docs/嵌入式面试准备_3年经验.md` (Q&A, 34 问, 对标 3 年经验)

## 已发现的关键坑（维护必知）
1. **App 运行地址不一致**: 链接脚本/VTOR = 0x08010000，但 `boot_manager.h::ApplicationAddress_boot=0x08008000`、`BackupApplicationAddress_boot=0x08020000`。两套地址表未对齐，是最大隐患。
2. `flash.c::flash_erase` 循环 `for(i=0;i<=12;i++)` 访问 12 项数组(0~11) → 越界读 UB。
3. `configCHECK_FOR_STACK_OVERFLOW=0`（栈溢出检测关闭，生产应开=2）。
4. ISR 里 `printf` 回显 + KEY 框架用 `xTaskGetTickCount()`（应为 FromISR 版）属错误写法。
5. AES 仅加密无签名验签；Bootloader 函数 `back_to_app` 读 0x08020000 与"下载到 W25Q64"实际路径不一致（旧设计残留）。

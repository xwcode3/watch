# 2026-08-12 工作日志

## AHT21 桥接驱动 IIC 接口挂载问题诊断
- 根因：AHT21 的 `iic_driver_interface_t` 被 `#ifdef HARDWARE_IIC` 切成两套不一致布局，但工程从未定义 `HARDWARE_IIC`（实际走软件 IIC）。
  `FreeRTOS_tasks.c` 却用 `IICInit/IICStart/IICSendByte/IICReceiveByte`（`iic_bus_t*` 硬件风格函数）填接口，与默认 `void*` 首参契约错配。
- 还有：结构体缺 `pf_critical_enter/exit`（driver 却调用）、初始化器漏 `wait_ack/send_ack/send_no_ack`、`temp_humi_input_arg` 字段未接、线程传 NULL 参数。
- 给出 Adapter 方案：统一 `iic_driver_interface_t` 为单一状态码契约，新增 `bsp_aht21_iic_adapter.c` 把 `iic.c` 的全局 `i2c_*`（软件 IIC）包成接口；并补 `i2c_Init()`、修正 `FreeRTOS_tasks.c` 接线。
- 产出文档：`docs/AHT21_IIC接口挂载修改建议.md`（用户要求不直接改源码，照文档手动改）。AHT21 driver .c 本身无需改动即可编译。

## 重要澄清（用户纠正）：IIC 开头的函数是软件 IIC，不是硬件 IIC
- 用户明确：要用 **`IIC` 开头**那组函数（`IICStart/IICStop/IICWaitAck/IICSendByte/IICReceiveByte/IICInit`…），注释写"硬件 IIC"但实际仍是**软件 IIC（位带）**，只是多了一个 `iic_bus_t *bus` 形参描述 SDA/SCL（非 MCU 硬件 I2C 外设）。
- 与 `i2c_*` 那组（硬编码 PB8/PB9、`void` 无 bus）是两套独立的软件 IIC。
- **关键语义差异（适配器必须处理）**：
  - `IICWaitAck(bus)` 返回 `1`=有 ACK（成功）、`0`=超时/NACK —— 与 `i2c_WaitAck()` 的 `0`=ACK 相反；
  - `IICReceiveByte(bus)` **直接返回字节值**，而接口槽位 `pf_iic_receive_byte` 要求经 `uint8_t * const` 出参带回。
- 因此 v2 文档改为：适配器持有静态 `iic_bus_t g_aht21_iic_bus`（SCL=PB8/SDA=PB9），wrapper 忽略 AHT21 传来的 `NULL` 形参、改用 `&bus` 调 `IIC*`；并补 `RCC_AHB1PeriphClockCmd(GPIOB)`（`IICInit` 内未开时钟）。
- 教训：写 IIC 适配器前先确认用户指的是 `IIC*` 还是 `i2c_*` 哪套，二者语义相反。

## IIC 驱动新增 `IICDeinit` 函数
- 用户要求给 `IIC*` 软件 IIC 加 `IICDeinit`（与 `IICInit` 对称）。当前 `iic.c` 只有 `IICInit`，无 deinit。
- 产出文档：`docs/IIC驱动添加IICDeinit函数.md`（不改源码，手动落地）。实现要点：SDA/SCL 配成输入浮空释放总线；**不要**关 GPIOB 时钟（EEPROM 等仍可能用 GPIOB）；加 NULL 防御。
- 并联动更新 v2 挂载文档的 `adapter_iic_deinit`：从占位的 `IICStop` 改为真正调用 `IICDeinit(&g_aht21_iic_bus)`。接口 `pf_iic_deinit` 成员已存在无需改。
